# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repository Is

The official index of IDA Pro plugins, maintained by Hex-Rays. It powers [plugins.hex-rays.com](https://plugins.hex-rays.com/) and the IDA Plugin Manager. The core data is `plugin-repository.json` — a JSON manifest of all discovered plugins, auto-updated every 4 hours via GitHub Actions.

## Key Files

- `plugin-repository.json` — master plugin registry (do not hand-edit; generated by `hcli`)
- `known-repositories.txt` — whitelist of GitHub repos the indexer crawls
- `ignored-repositories.txt` — blocklist of repos the indexer skips
- `tags.json` — plugin contest tags and special classifications
- `justfile` — build automation (use `just <recipe>`)

## Common Commands

All Python scripts use `uv run --script` (PEP 723 inline dependencies — no venv setup needed).

```bash
# Rebuild plugin-repository.json from source repos (requires local hcli install)
just build-repo

# Full public site build pipeline
just build-public

# Individual pipeline steps
just generate-chart       # plugin count chart → public/resources/repo_size.png
just collect-repo         # copy JSON manifests → public/
just mirror-content       # download/cache plugin archives → public/plugins/
just collect-stars        # fetch GitHub metadata → public/plugins/
just summarize-logs       # generate HTML indexer report → public/logs/indexer.html
just generate-hugo        # convert plugin data → Hugo markdown in site/content/
just hugo-build-site      # compile Hugo static site
just collect-site         # aggregate output → public/_/

# Sync known-repositories.txt with repos already in the manifest
just update-known-repos

# Lint a plugin archive (for plugin authors troubleshooting)
hcli plugin lint /path/to/plugin-archive.zip

# Clean build artifacts
just clean
```

## Architecture

### Data Flow

```
GitHub Repos → hcli indexer → plugin-repository.json
                                       ↓
                Python scripts (mirror, stars, charts, logs)
                                       ↓
                         Hugo site generation → public/
                                       ↓
                              GitHub Pages
```

### Pipeline Components

1. **Indexer** (`sync.yml` GitHub Action, every 4 hours): Runs `hcli plugin repo snapshot` against `known-repositories.txt`, writes `plugin-repository.json`, auto-discovers new repos, commits with AI-generated summary.

2. **Content pipeline** (Python scripts in `scripts/`): Each script takes `plugin-repository.json` as input and writes to `public/`. Scripts use uv inline dependencies — no separate install step.

3. **Hugo site** (`.github/pages/`): Static site generator config lives in `.github/pages/hugo.toml` and `.github/pages/layouts/`. The `generate-hugo` recipe populates `site/content/` from plugin data before `hugo-build-site` compiles it.

4. **Deploy** (`deploy.yml` GitHub Action): Triggered after a successful sync, builds the full public pipeline and pushes to GitHub Pages.

### Plugin Repository JSON Structure

The `plugin-repository.json` is generated exclusively by `hcli` — never hand-edited. It contains plugin metadata, version history, download URLs, and GitHub source references. The `plugins[].host` field holds the GitHub repo URL.

## Adding/Removing Plugins

- **Add a repo to index**: append to `known-repositories.txt`
- **Block a repo**: append to `ignored-repositories.txt`
- `just update-known-repos` syncs any repos already in the manifest back into `known-repositories.txt`
